Run `skif rules` (or `skif rules --format json`) to list the registry. Every rule has a stable kebab-case id, a
category and a default level. Rule pages on this site are generated from
[`docs/rules.md`](https://github.com/Goldziher/skif/blob/main/docs/rules.md) at build time.

## Levels

`off` disables a rule; `info`, `warn` and `error` set the severity. `info` never counts toward the exit code.
Set a level in `[rules]`, or per run with `--rule ID=LEVEL`.

## Fix safety

| Fixable | Meaning |
| --- | --- |
| `safe` | Applied by `--fix`. |
| `unsafe` | Applied only by `--fix-unsafe`; a fix that deletes a file also needs `--allow-remove-files`. |
| `sometimes` | Fixable for some findings, depending on the situation. |
| `none` | Reported only. |

A version alignment (`version-mismatch`, and `catalog-not-used` or `catalog-mismatch` moving to an existing catalog
entry) is `safe` when its target is explicit and the move stays within semver's compatibility window: a `pinned`
group's version, or the version the workspace aligns on when it is the same major (the same minor under `0.x`), not
lower, and written in the same shape (`1.0.0` to `1.3.0`, `^1.2.0` to `^1.4.0`). A move across a major, a downgrade
(`prefer = "lowest"`), a change of range (`^1.0.0` to `1.3.0`) and adding a catalog entry stay `unsafe`.
`types-in-dependencies` is `safe`. See [ADR 0051](https://github.com/Goldziher/skif/blob/main/adrs/0051-safe-version-alignment-fixes.md).

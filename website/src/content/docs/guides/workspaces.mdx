---
title: Single packages and monorepos
description: How skif finds the root, detects the package manager, and lints standalone packages and several projects in one run.
---

## Root

`skif [PATH]` lints the project containing `PATH` (default `.`). The project is the nearest directory at or above
`PATH` that holds a `package.json` or declares a workspace. A directory declares a workspace with `workspaces` in
`package.json` or a `pnpm-workspace.yaml`.

- If the project declares a workspace, it is the root.
- Otherwise the root is the nearest ancestor workspace that lists the project as a member, after negations. An
  ancestor workspace does not claim projects it does not list.
- Otherwise the project is its own root.

The root is used for configuration, every reported path, every fix write and the install step, so the result does not
depend on the current directory.

## Configuration lookup

`skif.toml` or `.skif.toml` is searched from the root upwards. In a single-root run the search stops at the root, so
only the root's own file counts. In a multi-root run (see below) each root takes the nearest file between the root
and the start directory, and a root with none uses the defaults; a file above the start directory is never read.
There are no per-package configuration files; per-package differences are expressed with `[[ignore]]`, group
selectors and `[js.workspaces."<dir>"]`.

## Package manager detection

First match wins:

1. `[workspace] package-manager` in `skif.toml`.
2. The root `package.json` `packageManager` field, then `devEngines.packageManager`.
3. Lockfile presence: `pnpm-lock.yaml`, `bun.lock` / `bun.lockb`, `yarn.lock`, `package-lock.json`.
4. A `pnpm-workspace.yaml` implies pnpm.

If nothing indicates a manager, skif does not guess npm. Rules and fixes that depend on the manager skip what
would be wrong for some manager; an npm workspace never receives a `workspace:*` specifier.

## Workspace patterns

Patterns follow pnpm semantics for every package manager: `dir/*` for direct children that contain a
`package.json`, `dir/**` for nested packages, and `!pattern` to remove matches. `node_modules` and
dot-directories are never entered.

## Monorepo configuration

```toml
[workspace]
ignore-packages = ["examples/*"]

[policy]
prefer = "highest"

[[version-groups]]
label = "Pin react across the repo"
dependencies = ["react", "react-dom"]
policy = "pinned"
pin = "19.1.0"

[[semver-groups]]
label = "Caret ranges for libraries"
packages = ["packages/*"]
range = "^"

[catalog]
mode = "prefer"
min-packages = 3
```

## Single packages

A package that declares no workspace is linted on its own; skif does not require a `workspaces` field or a
`pnpm-workspace.yaml`. A `pnpm-workspace.yaml` that holds only settings and no `packages:` key counts as no
declaration when it finds no package besides the root. In this single-package mode `root-package-private-field` and
`root-package-dependencies` do not report, because a standalone package is published and keeps its dependencies in
its own `package.json`. The other rules run unchanged; turn off those that do not fit with `[rules]`.

## Several projects

A repository can hold independent projects with no workspace at the top. `skif -r` (`--recursive`) lints every
workspace and standalone package at or below the start path in one run, and so does a plain `skif` started where
neither the path nor any ancestor holds a `package.json` or a workspace declaration.

```bash
skif -r                  # every root below the current directory
skif -r services         # every root below services/
skif -r --format json    # one document with a "roots" array
```

- A root is a workspace that no outer workspace lists as a member, or a package that declares no workspace, is
  listed by no workspace and does not lie inside a workspace member. Members are never roots of their own.
- A directory that declares a workspace is always a root of its own, also when it sits inside another workspace. A
  workspace needs no root `package.json`: a `pnpm-workspace.yaml` or a `rush.json` alone is enough, and the members
  are linted while the rules about the root manifest are skipped.
- A standalone package below another root (an example, a template) is linted, but `root-package-manager-field` does
  not report for it; the rule still reports for every workspace and for the outermost root.
- The search skips `node_modules`, hidden directories, symbolic links, anything a `.gitignore` or `.ignore`
  excludes, and the directories named by `[workspace] discover-ignore` (by default `__fixtures__`, `fixtures`,
  `__mocks__` and `__snapshots__`). It goes at most 32 directories deep.
- A root that cannot be loaded does not stop the others: it is listed in the `errors` array of the JSON document and
  the exit code is `2`.
- Roots are linted in parallel and merged into one report in path order. Paths are relative to the invocation
  directory, and the exit code is the worst over the roots. `--max-warnings` bounds the warnings of the whole run.
- `--fix` plans, writes and runs the package manager's install per root.
- If no root is found, skif exits with code `2` and says no workspace or package was found.

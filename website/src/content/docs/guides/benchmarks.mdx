Every speed number on this page comes from one run of the
[`bench` workflow](https://github.com/Goldziher/skif/blob/main/.github/workflows/bench.yml) on a GitHub-hosted
runner, and the agreement table from the committed parity baseline. Both are generated: the first line of each block
names the skif commit, the tool versions, the runner image and the machine, and the speed block links the
[workflow run](https://github.com/Goldziher/skif/actions/workflows/bench.yml) the numbers came from. How they are
measured is under [Methodology](#methodology).

## Speed

Full skif runs are timed against knip, and `skif --no-js`, which skips the JS analysis, against sherif and syncpack,
on the [pinned public repositories](https://github.com/Goldziher/skif/blob/main/tools/bench/corpus.toml) with their
dependencies installed and on generated workspaces. Absolute times depend on the machine; the ratios are the result.
On npm-cli knip runs with `--no-gitignore`, since npm's `.gitignore` otherwise hides every workspace from it.

## Accuracy on seeded defects

A generated 500-package workspace with defects injected on purpose. `Actual` is counted from the files, so the right
answer is known. Counted by hand on 2026-11-06 with skif 0.1.0 and not re-counted since; the method is in the
[benchmark harness](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md#seeded-defects):

| Defect | Actual | skif | sherif | syncpack |
| --- | ---: | ---: | ---: | ---: |
| Dependencies with mismatched versions | 200 | 200 | 200 | 200 |
| Unsorted dependency maps | 25 | 25 | 25 | n/a |
| Type packages in `dependencies` | 24 | 24 | 24 | n/a |
| Empty dependency objects | 31 | 31 | 31 | n/a |

skif and sherif name the same 200 dependencies. skif and syncpack report the same 4,568 mismatched instances, with
nothing unique to either. `n/a` means the tool does not check for that defect.

## Precision on seeded dead code

A generated 5-package workspace with seeded unused files, exports, types and dependencies, next to live code that is
reached only through patterns that caused false findings on real repositories (namespace reads, `typeof import()`,
`import.meta.glob`, tsconfig `paths`, `#` subpath imports, manual mocks, fixtures and more). The answer key lists all
33 seeded findings. skif measured on 2026-11-08 and knip 6.44.1 on 2026-11-07, not re-measured since;
reproduce with `mise run bench:deadcode -- --knip`:

| Tool | Precision | Recall |
| --- | ---: | ---: |
| skif | 100% | 100% |
| knip | 77% | 100% |

skif reports no false finding; knip reports exports read only through `typeof import("./m")["name"]` and files in
`fixtures` directories. Per issue type and pattern: the
[benchmark harness](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md#dead-code-precision-and-recall).

## Agreement with knip

Real repositories have no answer key for dead code, so this measures agreement, not correctness. A weekly job runs
both tools on pinned public repositories and compares the findings per issue type; the table is generated from the
committed baseline of that comparison:

A low share means the tools differ, and either one could be right. Some differences are intended and counted apart:
skif makes test files entries, does not report files in `fixtures` directories
([ADR 0014](https://github.com/Goldziher/skif/blob/main/adrs/0014-files-the-js-analysis-reads-walk-git-index-fixtures.md)), reads a
namespace import differently. Findings in packages skif does not judge, in packages where knip could not load a config,
inside a file the other tool reports as unused (the file is the one disagreement), and exports used only by such
files are counted apart too. So are declaration files, which skif never reports as unused, types named in the
signature of an export skif keeps
([ADR 0018](https://github.com/Goldziher/skif/blob/main/adrs/0018-export-namespace-and-member-rules.md)),
duplicate exports of entry modules, which skif's rule leaves alone, and dependencies a Bazel `BUILD` file names, which
knip does not read. It also sets apart what follows from where each tool looks, decided from paths and manifests:
projects with their own `package.json` that are not knip workspaces, on both sides (knip neither judges their
dependencies nor uses their entry files, while skif lints them as roots of their own), directories skif's file
discovery skips, and TypeScript sources whose built path a package publishes, also through a tsconfig `outDir` (and
the node and credential files an n8n node package lists), which skif makes entries, together with their exports and
the files they import that only knip reports as unused. An import one tool reports as unlisted and the other as
unresolved counts as agreement. A repository whose knip run is not a valid comparison is named and left out of the
sums. Reading the disagreements found false findings on both sides
([ADR 0013](https://github.com/Goldziher/skif/blob/main/adrs/0013-js-analysis-core-oxc-module-graph-and-resolution.md)).
The remaining differences, and what each tool reports differently, are in the
[comparison guide](../comparison/#parity-with-knip).

## Methodology

### What is measured

[`skif-bench run`](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md#what-it-measures) times whole
command-line invocations, process start-up included, on three kinds of targets:

| Target | Contents | Tools timed |
| --- | --- | --- |
| Generated workspaces | 50, 500 and 2000 packages, pnpm layout, 5% issue rate, seed 1 | `skif --no-js`, `sherif`, `syncpack lint` |
| Module graph | 10,000 TypeScript files in 100 packages | `skif` |
| Pinned corpus | the `bench` repositories of `corpus.toml` | `skif`, `skif --no-js`, `sherif`, `syncpack lint`, `knip --reporter json` |

skif runs as `skif . --format json --no-install`, with `--no-js` for the manifest and policy rows and with
`--recursive` where a repository sets `recursive` (babel); the working directory is the target. Non-zero exits are
ignored, since a linter exits 1 when it finds something; a run that exits above 1 or by a signal is an error, since its
time may be that of a partial run.

### Runs and statistics

[hyperfine](https://github.com/sharkdp/hyperfine) runs each command without a shell (`-N`), with 3 warmup runs and 15
measured runs by default (the workflow's `warmup` and `runs` inputs). The tables show medians, which one slow run does
not move. The warmup means the numbers are warm file cache, not cold start.

### Pinned corpus and tools

[`tools/bench/corpus.toml`](https://github.com/Goldziher/skif/blob/main/tools/bench/corpus.toml) pins every repository
to a full commit SHA and declares the sherif, syncpack and knip versions under `[tools]`. The harness installs those
versions with `npm ci --ignore-scripts` from `tools/bench/tools/package-lock.json`, refuses to run when the lock and
`[tools]` differ, and times the executables in `node_modules/.bin` directly, so no `npx` resolution is timed and
nothing on `PATH` is used. The harness fails before timing anything when a repository is not pinned to a full commit
SHA or a tool not to an exact version.

### Installed dependencies

knip needs installed dependencies to load the repositories' tool configurations, so the workflow installs each corpus
repository first (`run --install`), through a pinned corepack whose pnpm and yarn shims follow the repository's
`packageManager`. Installing changes the timings of every tool, not only knip's, so compare only runs made the same
way. Where knip fails even installed, for reasons that are the repository's own, `corpus.toml` declares the failure
(`bench-knip-failure`); a run whose error matches is published as `fails: <reason>`, without a ratio, and any other
error stops the run from being published.

### The runner

The workflow runs only when dispatched, on a pinned GitHub-hosted runner image (`ubuntu-24.04` or
`ubuntu-24.04-arm`), and builds skif and the harness with `--locked` and the `rust-version` of their `Cargo.toml`
([ADR 0029](https://github.com/Goldziher/skif/blob/main/adrs/0029-performance-caching-and-benchmarks.md)).
GitHub-hosted runners are shared virtual machines: a neighbour's load moves the times of a run by several percent, and
two runs of the same image may land on different CPU models (the summary names the one it got). Read the ratios
against knip, sherif and syncpack, which share the machine and its noise, rather than the absolute times.

### Publishing a run

`mise run bench:import -- <run-id>` imports only a successful, dispatched run of `bench` whose commit is on `main`,
puts its summary and raw hyperfine exports into
[`tools/bench/results`](https://github.com/Goldziher/skif/tree/main/tools/bench/results), and regenerates the blocks of
this page and the headline claims of the README and the [comparison guide](../comparison/#performance). It writes
nothing when a comparison tool was not timed, the run was narrowed to some repositories, a tool exited with an error
that is not a declared knip failure, an ADR 0001 check is invalid, or the run did not come from clean checkouts on a
GitHub-hosted runner. The headline claims give, for each tool, the range of the ratios of its median to skif's over
the targets it completed on, with the median ratio from three targets on, each rounded down to one decimal.

### Reproducing

```sh
gh workflow run bench.yml -f ref=main -f runner=ubuntu-24.04   # also: -f runs=15 -f warmup=3 -f only=babel
gh run list --workflow bench.yml --limit 1                     # the run id
mise run bench:import -- <run-id>
```

On your own machine, `mise run bench` builds skif in release mode and times it the same way (it needs hyperfine and
npm); add `--install` to `skif-bench run` to install the corpus first, as the workflow does. Local numbers are not
published. `mise run bench:deadcode -- --knip` reproduces the precision table, and
`mise run parity -- --install --write-baseline` followed by `mise run parity:publish` the agreement table. The
[benchmark harness](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md) documents every command and
option.

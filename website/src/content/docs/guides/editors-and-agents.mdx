skif runs as a server for the tools you write code with. The servers and watch mode are part of the `skif` binary;
nothing else to install. The design is recorded in
[ADR 0013](https://github.com/polylint/skif/blob/main/adrs/0013-editors-agents-and-git-hooks.md).

## Agent skill

The repository ships an [agent skill](https://agentskills.io) that teaches a coding agent when and how to run skif:
the lint, triage and fix loop, reading the JSON report, configuring `skif.toml`, migrating from sherif, syncpack and
knip, and CI. It lives in
[`skills/skif`](https://github.com/polylint/skif/tree/main/skills/skif) and is installed straight from GitHub. The
skill runs the `skif` command, so [install skif](../../start/installation/) as well (or let the agent use
`npx @polylint/skif`).

Any agent that reads Agent Skills, with the [`skills`](https://www.npmjs.com/package/skills) installer:

```sh
npx skills add polylint/skif
```

As a plugin, in Claude Code (in the session, not the shell):

```text
/plugin marketplace add polylint/skif
/plugin install skif@skif
```

or, from Claude Code 2.1.275 on, `/plugin install skif --marketplace polylint/skif` in one step.

Codex:

```sh
codex plugin marketplace add polylint/skif
codex plugin add skif@skif
```

Factory Droid:

```sh
droid plugin marketplace add https://github.com/polylint/skif
droid plugin install skif@skif
```

GitHub Copilot CLI:

```sh
copilot plugin marketplace add polylint/skif
copilot plugin install skif@skif
```

The plugin holds the skill and registers the [MCP server](#mcp-server-for-agents) as `skif`, started with
`npx -y @polylint/skif@<version> mcp`, where `<version>` is the release the plugin documents. The server needs Node.js 22
or later with npm on `PATH`, not an install of skif; its first start downloads the npm package. Without npm the
server fails to start and the skill still works. The plugin's version is the skif release it documents, so a plugin
manager that updates on a version change picks up each release, and its server with it. The design is recorded in
[ADR 0013](https://github.com/polylint/skif/blob/main/adrs/0013-editors-agents-and-git-hooks.md).

## MCP server for agents

`skif mcp` is a [Model Context Protocol](https://modelcontextprotocol.io) server on stdio. Each tool runs one
command with `--format json` and returns the document it prints, as structured content and as compact JSON text. An
argument is the flag of the same name (`max_show_issues` is `--max-show-issues`), parsed by the command line itself,
so a bad value gets the command's own message.

| Tool | Command | Arguments |
| --- | --- | --- |
| `lint` | `skif` | `path` (default `.`), `recursive`, `config`, `no_config`, `include`, `exclude`, `workspace`, `production`, `strict`, `no_js`, `max_show_issues`; `fix`, `fix_unsafe`, `fix_type`, `select`, `allow_remove_files` plan fixes as `--dry-run` does and add `fix.changes` |
| `explain_usage` | `skif explain-usage` | `file`, `export`, or `dependency` with `package`; `path` (default `.`), `production`, `config`, `no_config` |
| `config` | `skif config` | `path`, `recursive`, `explain` with `package`, `config`, `no_config`; without `explain` it is `--show` |
| `list_rules` | `skif rules` | none |
| `cache_stats` | `skif cache stats` | `path` (default `.`), `cache_location` |
| `cache_clean` | `skif cache clean` | `path` (default `.`), `cache_location`, `all` |

Paths, `file` included, are relative to the directory the server was started in, so start it in the repository.
Problems in the project are the report, not an error. A command that exits `2` gives a result flagged `isError`:
the JSON `error` document with its `kind` and message, or, when roots of a recursive run failed, the report with its
`errors`. The server writes no project file: to apply fixes, run `skif --fix`. `cache_clean` removes only skif's own
[cache](#the-module-cache) stores, and the `lint` tool never writes the cache. The tools' annotations say so:
`cache_clean` is the one tool not marked read-only, and it is marked destructive.

The server handles one call at a time: a `lint` of a large monorepo holds every later request until it finishes,
and cancelling a call does not stop it. A message longer than 64 MiB is refused.

Claude Code:

```sh
claude mcp add skif -- skif mcp
```

Clients configured with an `mcpServers` object, such as Cursor's `.cursor/mcp.json` and Claude Desktop (VS Code's
`.vscode/mcp.json` names the object `servers`):

```json
{
  "mcpServers": {
    "skif": { "command": "skif", "args": ["mcp"] }
  }
}
```

With the npm package and no global install, use `"command": "npx", "args": ["-y", "@polylint/skif", "mcp"]`; the
[plugin](#agent-skill) registers this form, pinned to its release. The server speaks the protocol
revisions `2025-11-25`, `2025-06-18`, `2025-03-26` and `2024-11-05`.

## Watch mode

`skif --watch [PATH]` lints, then lints again whenever a file below the root changes, until you press Ctrl-C. Every
other lint flag applies to each run. With human output on a terminal the screen is cleared before each run; with
`--format json` stdout holds one JSON document per run. Several `--format FORMAT=FILE` reports can be written per
run; the watcher ignores the files it writes itself (those and `--output`), so they do not start another run.

The watcher checks the files below the root every 200 milliseconds (longer in a repository whose scan takes
longer), skips `node_modules`, `.git` and `target`, and honours `.gitignore`, so build output does not trigger a
run. A run starts once the tree has been quiet for 100 milliseconds, so a branch switch or a formatter that touches
many files causes one run. Each check walks the tree and reads the size and modification time of every file, so it
costs more in a large repository; the interval stretches to twice the time a scan takes, which keeps the watcher
to at most about a third of one core. When the configuration cannot be read, the error is printed and the watcher keeps going,
so the next save of `skif.toml` runs again. `--watch` cannot be combined with `--fix` or `--fix-unsafe`.

With `--performance` or `SKIF_TIMINGS=1`, the phase timings of each run are written to stderr when the run ends.
`skif lsp` and `skif mcp` with `SKIF_TIMINGS=1` write them after each message or request.

## The module cache

Parsing source files is the largest part of a JavaScript analysis. skif keeps the parse result of each file in a cache
under a key of the file's name, its text, the relevant options and the parser's version, never its modification time
or absolute path, so an unchanged file is not parsed again and a changed file always is. The cache never changes a
report or an exit code. Everything else (configuration, manifests, the module graph, the rules) is computed on every
run. A store that is damaged, written by another version or unreadable is empty, and an entry that does not verify is
a miss. The design is recorded in
[ADR 0007](https://github.com/polylint/skif/blob/main/adrs/0007-js-analysis-core-on-oxc.md), and what a warm cache
saves on real repositories is measured on the [benchmarks page](../benchmarks/#warm-cache).

The cache is on by default for `skif`, `skif -r` and `--watch`. Turn it off with `--no-cache`, `SKIF_CACHE=0` or
`[cache] enabled = false`. A setting comes from the first of these that sets it: the flags (`--no-cache`, `--cache`,
`--cache-location <DIR>`, `--cache-max-size <SIZE>`), the environment (`SKIF_CACHE`, `SKIF_CACHE_DIR`,
`SKIF_CACHE_MAX_SIZE`), the [`[cache]` table](../../reference/configuration/#cache) of the root configuration, then the
defaults: on, capped at 512 MiB. `--cache` only forces the cache on over `SKIF_CACHE=0` or `enabled = false`.

- **Location.** The first that applies: `--cache-location`, `SKIF_CACHE_DIR`, `[cache] location`; then
  `$TEST_TMPDIR/skif` under `bazel test`; then `node_modules/.cache/skif` below the workspace root (or the invocation
  directory of a multi-root run), only when `node_modules` exists, because skif never creates it; then the per-user
  cache directory (`$XDG_CACHE_HOME/skif` when set, else `~/Library/Caches/skif` on macOS, `%LOCALAPPDATA%\skif` on
  Windows, `~/.cache/skif` elsewhere); with none of these, memory for the run. A directory skif creates gets a
  `CACHEDIR.TAG` and a `.gitignore` of `*`, so version control and backup tools skip it.
- **Layout.** One location holds one store per project, `<location>/<key>/modules.bin`. Inside a git repository the
  key comes from the repository (the git directory its worktrees share) and the base directory's path in it, so the
  worktrees of one repository share a store and two repositories, or two clones of one, never do; outside git it
  comes from the absolute path. A `modules.bin` that an older skif left directly in the location is ignored and can
  be deleted.
- **Eviction.** A store keeps exactly what the project's last complete run used, so it does not grow with edits, and
  a narrower run (`--production`, one root of several) drops the entries it did not use: alternating `skif` and
  `skif --production` on one store parses the difference again each time, so give one of them its own
  `--cache-location`. A run that fails, or in which a root cannot be linted, only adds what it parsed and drops
  nothing. After a write, a location over its cap drops the stores of other projects, least recently written first;
  a cap from `[cache] max-size` shrinks only the project's own store.
- **Failures.** A store that cannot be written is silent when the cache came from the defaults (one `skif debug:` line
  under `--debug`) and a `warning:` on stderr when you asked for the cache, by turning it on or naming a location. The
  exit code stays unchanged. A write goes to a new, randomly named temporary file and replaces the store's file
  atomically behind a try-lock, so a concurrent run skips its write rather than waiting; a temporary file a killed run
  left is removed by the next write. A store file larger than the cap is not read.
- **`--debug`** prints `skif debug: cache store <dir>` and `skif debug: cache modules: H hits, M misses, B bytes written`.
  A warm run still reads every file, so the gain is the parse share of a run, which `--performance` shows as
  `js parse` beside `js module cache: H hits, M misses, W waits`.
- **`skif cache stats` and `skif cache clean`** show and remove the stores of a location
  ([CLI](../../reference/cli/#managing-the-cache)); neither writes a project file.
- **`skif -r`** shares one cache between its roots for the files more than one root can reach: files outside the root
  parsing them (shared code outside every root) and files of a root nested in it. Such a file is parsed once, not
  once per root; roots linted in parallel wait for a parse already under way rather than repeating it, which
  `--performance` counts as waits and reports as `js parse wait`. With `--no-cache` each root parses its own files
  without the cache and only these shared files are kept, in memory.
- **`--watch`** reads the store once and writes it after each run; the cache location is left out of the files it
  watches. With `--no-cache` it keeps the cache in memory across its runs.
- **`skif lsp`** and **`skif mcp`** keep one cache in memory per project, for as long as the server runs. The
  project's first lint is seeded from the store, which is then let go; the servers never write it.

### Caching in CI

With `CI` set and no location given by `--cache-location` or `SKIF_CACHE_DIR`, a run reads the store but does not
write it: nothing would restore what it wrote. A `[cache] location` in `skif.toml` does not change that, since a
configuration file is part of the checkout. The store's key includes the path of the repository's git directory,
so restore the cache into a checkout at the same path, as GitHub-hosted runners give. To cache in CI, name a directory and restore and save
it with the CI's cache step, keyed on what changes the entries (the lockfile and `skif.toml`):

```yaml
env:
  SKIF_CACHE_DIR: ${{ github.workspace }}/.skif-cache
steps:
  - uses: actions/cache@v6
    with:
      path: .skif-cache
      key: skif-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml', '**/skif.toml') }}
      restore-keys: skif-${{ runner.os }}-
  - run: skif
```

On GitLab CI, set `SKIF_CACHE_DIR: $CI_PROJECT_DIR/.skif-cache` in `variables:` and add
`cache: { paths: [.skif-cache] }`. The `npm` package follows the same rule.

## Language server

`skif lsp` is a minimal [Language Server Protocol](https://microsoft.github.io/language-server-protocol/) server on
stdio. When the editor opens or saves a file, skif lints the project that contains it and publishes the diagnostics
of every file of that project, with the rule ID as the code and `skif` as the source; a file whose findings are gone
gets an empty list.

It lints what the editor holds, not only what is saved: the open documents' unsaved text replaces the files on
disk for the lint, so a manifest, `pnpm-workspace.yaml`, `skif.toml` or source file is linted as you type. The
server asks for the full text on every change (`textDocumentSync.change: 1`) and lints a project 250 milliseconds
after its last change, so a burst of keystrokes causes one lint; opening or saving a file lints at once, and so
does closing a file without saving its changes, since the file on disk counts again. While a lint
runs the server answers nothing else. A new file that was never saved is not linted until it exists on disk, and
files changed outside the editor are seen on the next lint of their project. Each project keeps an in-memory
[module cache](#the-module-cache), so a lint parses only the files that changed.

### Code actions

The fixes of the last lint are offered as code actions, planned exactly as `skif --fix --dry-run` plans them, and
the editor applies them; the server writes nothing.

- **Quick fixes.** Each fix of a diagnostic under the cursor is a `quickfix` with the fix's title. A safe fix that is
  the diagnostic's only fix is marked preferred. An unsafe fix (one that `skif --fix` leaves to `--fix-unsafe`) is
  offered too, with `(unsafe)` after its title and never preferred: choosing it is the explicit consent the flag
  stands for. A diagnostic with several alternatives gets one action per alternative.
- **Fix all.** `source.fixAll.skif` applies every safe fix of the file's diagnostics in one edit, taking the
  alternative `[policy] prefer` names where there are several, as a non-interactive `skif --fix` does. Editors run
  it from a "fix all" command or on save; in VS Code, `"editor.codeActionsOnSave": { "source.fixAll.skif": "explicit" }`.

A fix that creates or deletes a file (such as the `unused-files` fix) is not offered: deleting files stays a
command-line opt-in (`--allow-remove-files`). A fix for a document with unsaved changes edits the text the editor
holds. It is offered only while every open document it edits still has the text the last lint read; after a
further change it waits for the next lint. When the editor supports `documentChanges` in a workspace edit, the edit
of an open document carries the document's version, so the editor refuses it if the text changed in between.

A message larger than 64 MiB, or one whose header the server cannot read, ends the session: skif prints the reason
to stderr and exits with code 1, and the editor can restart it.

There is no skif editor extension
([ADR 0013](https://github.com/polylint/skif/blob/main/adrs/0013-editors-agents-and-git-hooks.md)). Any editor that can start
a language server for JSON files can run it; VS Code needs a generic language-server client extension for that. For
example Neovim:

```lua
vim.lsp.config("skif", {
  cmd = { "skif", "lsp" },
  filetypes = { "json", "javascript", "typescript" },
  root_markers = { "package.json" },
})
vim.lsp.enable("skif")
```

or Helix, in `languages.toml`:

```toml
[language-server.skif]
command = "skif"
args = ["lsp"]

[[language]]
name = "json"
language-servers = ["vscode-json-language-server", "skif"]
```

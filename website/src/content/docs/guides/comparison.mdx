skif builds on three projects and does not claim to replace them yet. This comparison is about scope.

| Tool | Scope | Relation to skif |
| --- | --- | --- |
| [sherif](https://github.com/QuiiBz/sherif) | Zero-config monorepo manifest rules | skif began as a fork; the manifest rules are ported with stable ids and `skif.toml` configuration. |
| [syncpack](https://github.com/JamieMason/syncpack) | Version consistency, semver ranges, catalogs | Same problem space; skif's policy rules reuse syncpack's specifier model, vendored in `skif-specifier`. |
| [knip](https://github.com/webpro-nl/knip) | Unused files, exports and dependencies | Same problem space; skif's analysis runs on oxc, with static config extraction instead of running tools. |
| [manypkg](https://github.com/Thinkmill/manypkg) | Workspace consistency checks and fixes | Overlapping manifest checks; skif adds a rule registry, severities and a library API. |

skif offers all three kinds of checks in one tool with one configuration file and one report format.

## Parity with knip

The JS analysis follows knip's issue types and its knowledge of tools. It is not a drop-in replacement: a weekly job
runs both tools on a pinned corpus of public repositories and compares the findings per issue type. They differ
where they model things differently, for example in which files count as unused (skif treats test files and fixture
directories as outside the project), and in how a namespace import is read. The harness names the intended
differences and counts them apart; see the
[benchmark harness](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md).

## Configuration

skif reads `skif.toml` or `.skif.toml` only. It does not read `sherif`, `.syncpackrc` or `knip.json`
configuration at lint time; `skif migrate` translates it once into a `skif.toml` (see the
[migration guide](../migrating/)). Rule ids are stable kebab-case names; rules ported from sherif list their sherif
name on the [rules pages](../../rules/).

## Performance

A benchmark harness lives in
[`tools/bench`](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md) and measures full CLI
invocations with hyperfine against generated workspaces and a pinned corpus. Run `mise run bench` to reproduce
it on your machine; this site makes no performance claims beyond what that harness measures.

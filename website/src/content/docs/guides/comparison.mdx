title: Comparison

skif builds on three projects and covers their three jobs in one tool. They remain excellent, focused tools.

| Tool | Scope | Relation to skif |
| --- | --- | --- |
| [sherif](https://github.com/QuiiBz/sherif) | Zero-config monorepo manifest rules | skif began as a fork; the manifest rules are ported with stable ids and `skif.toml` configuration. |
| [syncpack](https://github.com/JamieMason/syncpack) | Version consistency, semver ranges, catalogs | Same problem space; skif's policy rules reuse syncpack's specifier model, vendored in `skif-specifier`. |
| [knip](https://github.com/webpro-nl/knip) | Unused files, exports and dependencies | Same problem space; skif's analysis runs on oxc, with static config extraction instead of running tools. |
| [manypkg](https://github.com/Thinkmill/manypkg) | Workspace consistency checks and fixes | Overlapping manifest checks; skif adds a rule registry, severities and a library API. |

skif offers all three kinds of checks in one tool with one configuration file and one report format.

## Parity with knip

The JS analysis follows knip's issue types and its knowledge of tools. It is not a drop-in replacement: a weekly job
runs both tools on a pinned corpus of public repositories and compares the findings per issue type. They differ
where they model things differently, for example in which files count as unused (skif makes test files entries and
does not report files in `fixtures` directories), and in how a namespace import is read. The harness names the
intended differences and counts them apart, as it does findings in packages skif does not judge (a tool config it
cannot read) and in packages where knip could not load a config; see the
[benchmark harness](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md).

knip does not read the specifiers of test-runner mocks. skif does: a `vi.mock`, `jest.mock` or `jest.requireActual`
keeps the file it names in use, and a relative or aliased mock of a file that does not exist is reported by
`stale-mocks`, an error that knip has no counterpart for (`skif migrate --profile exact` turns it off). Such a mock
is not an `unresolved-imports` finding, so unresolved imports compare with knip's `unresolved`.

## Configuration

skif reads `skif.toml` or `.skif.toml` only. It does not read `sherif`, `.syncpackrc` or `knip.json`
configuration at lint time; `skif migrate` translates it once into a `skif.toml` (see the
[migration guide](../migrating/)). Rule ids are stable kebab-case names; rules ported from sherif list their sherif
name on the [rules pages](../../rules/).

## Performance

Medians of 15 runs on a 4-vCPU Linux VM (Intel Xeon at 2.10 GHz) with no other work running, on pinned public
repositories with dependencies installed, measured on 2026-11-08 after 0.1.1. Absolute times depend on the machine; the
ratios are the result. `skif` is a full run; `skif --no-js` skips the JS analysis. knip completes its analysis on all
five: on create-t3-turbo and vue-core it then exits with an error because some tool configurations do not load, and on
npm-cli it runs with `--no-gitignore`, since npm's `.gitignore` otherwise hides every workspace from it.

| Repository | skif | knip | skif --no-js | sherif | syncpack |
| --- | ---: | ---: | ---: | ---: | ---: |
| create-t3-turbo | 32 ms | 2.0 s | 4.6 ms | 36 ms | 41 ms |
| vue-core | 62 ms | 1.7 s | 5.5 ms | 36 ms | 43 ms |
| tanstack-query | 375 ms | 4.5 s | 11 ms | 42 ms | 106 ms |
| babel | 884 ms | 7.2 s | 9.4 ms | 37 ms | 280 ms |
| npm-cli | 99 ms | 968 ms | 5.3 ms | 38 ms | 77 ms |

On generated workspaces `skif --no-js` takes 6.3 ms, 27 ms and 102 ms at 50, 500 and 2,000 packages, against sherif's
39 ms, 59 ms and 130 ms: 1.3 times faster than sherif at 2,000 packages, where skif reports about 24,700 diagnostics and
sherif 638.

## Accuracy

On a generated workspace with injected defects, where the answer is known, skif, sherif and syncpack found every
defect they check for. A generated workspace with seeded dead code and live code behind known traps has an answer key
too: skif and knip both find every seeded finding, with a precision of 100% for skif and 77% for knip
(6.44.1, measured on 2026-11-07; it reports exports read through `typeof import("./m")["name"]` and fixture files). Real repositories have no answer key, so against knip the measure is agreement: on 9 pinned repositories
the tools share 98% of skif's unused exports, 98% of its unused files and 60% of its unused dependencies, while skif
finds 94% of knip's unused exports and 78% of its unused dependencies. Findings in fixtures, tests, packages skif does
not judge and packages where knip could not load a config are counted apart. The full tables are in the
[README](https://github.com/Goldziher/skif#benchmarks) and the
[benchmark harness](https://github.com/Goldziher/skif/blob/main/tools/bench/README.md), which reproduces them with
`mise run bench:publish`.

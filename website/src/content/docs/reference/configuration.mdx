skif reads TOML files named `skif.toml` or `.skif.toml`. A root takes the files from its own directory up to the
root of the git repository and merges them (see [Layered configuration](#layered-configuration)). Having both names
in one directory is an error naming both paths. There is no `package.json` key, no JSON, YAML or JavaScript variant, and no compatibility reader for sherif,
syncpack or knip configuration. `skif init` writes a starter file and `skif schema` prints its JSON Schema.

Keys are kebab-case, matching rule ids. Unknown keys and wrong types are errors that name the file, line and key.

## Precedence

Defaults, then the files, then the command line (`defaults < files < CLI`). Each layer sets only the keys it
contains, and arrays replace rather than append, except where a key says otherwise (see below). Within the files,
the order is the base of each file from the farthest to the nearest, then `[js.workspaces]`, then package files.
`[[overrides]]` apply on top of the base to the packages and files they select.

## Editor support

`skif init` writes a `#:schema` directive, so editors with Taplo or Even Better TOML validate and complete the
file. Print the schema with `skif schema`.

## Sections

| Section | Holds |
| --- | --- |
| `[workspace]` | `ignore-packages`, `package-manager`, `discover-ignore` |
| `[lint]` | `fail-on-warnings` |
| `[rules]` | Per-rule levels and options |
| `[[ignore]]` | Suppressions |
| `[policy]` | `prefer`, `dependency-types` |
| `[[version-groups]]` | Version policies per dependency group |
| `[[semver-groups]]` | Range policies per dependency group |
| `[catalog]` | Catalog enforcement |
| `[workspace-protocol]` | `workspace:` protocol policy |
| `[[dependency-families]]` | Packages that must share a version |
| `[js]` | JavaScript analysis |
| `root`, `extends`, `reset` | How files combine |
| `[[overrides]]` | Rule levels, severity caps, suppressions and JS inputs for selected packages or files |

### `[workspace]`

```toml
[workspace]
ignore-packages = ["examples/*", "!examples/keep"]
package-manager = "pnpm"   # npm | pnpm | yarn | bun; overrides detection
discover-ignore = ["fixtures", "e2e/cases"]   # directories `skif -r` does not search for roots
```

`discover-ignore` takes gitignore-style patterns relative to the directory the run starts in: a bare name matches at
any depth, a pattern with a slash is anchored there, and `!` re-includes. It replaces the default list
(`__fixtures__`, `fixtures`, `__mocks__`, `__snapshots__`); `[]` skips nothing. It is read from the configuration
file that governs the start directory and only affects root discovery in a recursive run.

### `[lint]`

```toml
[lint]
fail-on-warnings = true    # exit non-zero when only warnings were reported
```

### `[rules]`

A rule is a level string, or a table with a `level` and the rule's own options. `severity` is accepted as an alias of
`level`; setting both in one table is an error, and neither name can be a rule option.

```toml
[rules]
unsorted-dependencies = "warn"      # off | info | warn | error
empty-dependencies = "off"
member-toolchain-fields = { level = "error", mode = "match-root" }
unused-exports = { ignore-tags = ["lintignore"] }
```

Rules with options:

| Rule | Option | Values |
| --- | --- | --- |
| `member-toolchain-fields` | `mode` | `forbid` (default) reports every `packageManager` or `engines` field a member declares; `match-root` allows a field equal to the root's. |
| `unused-exports`, `unused-types` | `ignore-tags` | JSDoc tag names, without the `@` (a list of strings), that exempt an export. It is read from `unused-exports` and applies to `unused-types` as well. `public`, `beta` and `alpha` always exempt. |

An unknown option is an error that names the rule.

An unknown rule id is rejected with a closest-match suggestion. See the [rules](../../rules/) for ids.

### `[[ignore]]`

Each entry narrows by `rules`, `packages` and `dependencies`. An empty list does not narrow that dimension, but at
least one list must be set.

```toml
[[ignore]]
rules = ["types-in-dependencies"]
packages = ["legacy-app"]

[[ignore]]
dependencies = ["left-pad"]
```

### `[policy]`

```toml
[policy]
prefer = "highest"                   # highest | lowest
dependency-types = ["peer"]          # empty means dependencies and devDependencies; name peer or optional to include them
```

### `[[version-groups]]`

The first matching group wins. Selectors accept `!` negation, and `$LOCAL` selects dependencies that are
themselves workspace packages.

| Key | Meaning |
| --- | --- |
| `label` | Optional name shown in diagnostics. |
| `dependencies`, `packages`, `dependency-types`, `specifier-types` | Selectors. |
| `policy` | `preferred-semver` (default), `pinned`, `banned`, `ignored`, `same-range`, `same-minor` or `snapped-to`. |
| `pin` | Required by `pinned`. |
| `snap-to` | Required by `snapped-to`: packages whose version the group follows. |
| `prefer` | With `preferred-semver`, overrides `[policy] prefer`. |

```toml
[[version-groups]]
label = "Pin react"
dependencies = ["react", "react-dom"]
policy = "pinned"
pin = "19.1.0"

[[version-groups]]
label = "No moment"
dependencies = ["moment"]
policy = "banned"
```

### `[[semver-groups]]`

```toml
[[semver-groups]]
label = "Libraries use caret ranges"
packages = ["packages/*"]
range = "^"      # one of * ^ ~ > >= < <=
```

### `[catalog]`

```toml
[catalog]
mode = "prefer"              # off | prefer | enforce
min-packages = 2             # packages using a dependency before an entry is suggested
exclude = ["typescript"]
report-unused-entries = true  # default false: `unused-catalog-entries` reports nothing unless this is set
```

### `[workspace-protocol]`

```toml
[workspace-protocol]
internal = true              # require workspace: for dependencies on workspace packages
allow-local-paths = false    # accept file:/link: paths for internal dependencies
```

The rule is silent for npm and Yarn Classic workspaces, which cannot install the protocol, and for
`peerDependencies`, which a published library names by range. While `local-path-dependency` is on, `file:`/`link:`
paths are left to that rule so one dependency is not reported twice; `allow-local-paths` only decides them when
`local-path-dependency` is off.

### `[[dependency-families]]`

```toml
[[dependency-families]]
name = "babel"
packages = ["@babel/*"]

[[dependency-families]]
name = "react"
enabled = false              # disable a built-in family of the same name
```

### `[js]`

```toml
[js]
enabled = true
entry = ["src/index.ts"]
project = ["src/**/*.ts"]
ignore = ["**/*.generated.ts"]
ignore-dependencies = ["@types/node"]
ignore-binaries = ["docker"]
production = false
include-entry-exports = false

[js.workspaces."packages/web"]
entry = ["src/main.tsx"]

[js.plugins]
vitest = true
jest = { enabled = true, config = ["jest.config.cjs"] }
```

`enabled` defaults to `true`, so a plain `skif` run checks everything; the git hooks pass `--no-js`. Per-workspace
tables take `entry`, `project`, `ignore`, `ignore-dependencies` and `ignore-binaries`. A plugin entry is `true`,
`false` or a table with `enabled`, `config`, `entry` and `project`.

A dependency counts as listed when the package's own `package.json`, the `package.json` of a package that contains
it, or any `package.json` above the analysed root up to the git repository root lists it; the same manifests enable
plugins.

The default `project` globs include `.vue`, `.svelte` and `.astro` files. Their `<script>` blocks (`<script setup>`,
`<script context="module">`, any `lang="ts"` or `lang="tsx"`) and the Astro frontmatter are analysed as modules, with
diagnostics located in the original file. The markup is scanned for identifiers, not compiled: component tags
(`<MyCard>`, `<my-card>`, `<ui.Card>`), the expressions of `{{ }}`, `{ }`, `:prop`, `v-*`, `@event`, Svelte blocks
(`{#if x}`) and directives (`use:action`) count as uses of the imports they name, and a read such as `ns.member` counts as
a use of that member. `<style>` blocks and `src` attributes of `<script>` and `<style>` tags are imports. Matching is by
name, so a template variable that shadows an import hides it from the unused check, and nothing in a template is
type-checked. Imports of one script block count as used when another block reads them.

Test files are entries when a test-runner plugin is enabled (Jest, Vitest, Mocha, Playwright, Cypress and the like),
with the patterns of that plugin; a project without a runner reports unused test files like any other, as knip does.
Add other test files to `entry`. Directories named `fixtures` or `__fixtures__` hold test data: their imports are not checked for unresolved or
unlisted packages. Other directories of test data (`api-fixtures`, `__testfixtures__`) and other test file names
(`*_spec.*`) go on `ignore` and `entry`. In a package whose `exports` contain a wildcard (`"./*": "./src/*.ts"`) the
`*` matches across directories, as in Node.js, so every file it matches is an entry; the catch-all `"./*"` and the `main`, `bin` and `types` fields are not widened. In an enum or a namespace, a
member read in its own file (`E.A`, `E["A"]`, `const { A } = E`) counts as used; using the whole enum there
(`Object.values(E)`, `E[key]`, a spread, passing it as a value) or mentioning its type (`x: E`, `typeof E`) credits no
member, as in knip. A file that another loads with `new URL("./x", import.meta.url)` is used as a
whole.

The table holds 102 built-in plugins:

`typescript`, `eslint`, `prettier`, `vite`, `vitest`, `jest`, `next`, `storybook`, `playwright`, `tailwind`, `postcss`, `babel`, `webpack`, `rspack`, `rollup`, `tsup`, `turbo`, `husky`, `lint-staged`, `commitlint`, `changesets`, `github-actions`, `mastra`, `aws-cdk`, `browser-extension`, `tsdown`, `oxlint`, `angular`, `karma`, `esbuild`, `svelte`, `nuxt`, `astro`, `drizzle`, `ts-node`, `tsx`, `nx`, `cypress`, `mocha`, `sveltekit`, `prisma`, `graphql-codegen`, `docusaurus`, `vitepress`, `wrangler`, `expo`, `react-native`, `metro`, `release-it`, `semantic-release`, `lefthook`, `simple-git-hooks`, `stylelint`, `markdownlint`, `cspell`, `nodemon`, `pm2`, `pnpm`, `yarn`, `syncpack`, `node`, `expo-router`, `tanstack-router`, `ava`, `biome`, `c8`, `dotenv`, `electron-vite`, `gatsby`, `i18next-parser`, `jasmine`, `knex`, `lingui`, `msw`, `nest`, `netlify`, `nitro`, `nyc`, `oclif`, `panda-css`, `plop`, `preconstruct`, `react-router`, `remark`, `remix`, `rolldown`, `rsbuild`, `rslib`, `sanity`, `sentry`, `size-limit`, `stryker`, `svgo`, `svgr`, `swc`, `tsd`, `typedoc`, `unbuild`, `unocss`, `vercel`, `vike` and `webdriver-io`.

## Layered configuration

A root takes every configuration file from its own directory up to the root of the git repository (the nearest
directory with a `.git` entry, a directory or a worktree file), farthest first, and merges them. Outside a repository
the search covers the root alone in a single-workspace run and the start directory in a recursive run. A file above
the repository is never read. A file with `root = true` ends the search at itself. `skif` inside a project and `skif
-r` from the top therefore give that project the same configuration. The guide
[Sharing configuration](../../guides/sharing-configuration/) shows complete examples.

### `root`, `extends` and `reset`

```toml
root = true
extends = ["../presets/node-cli.toml"]
reset = ["version-groups"]
```

- `root = true` stops the upward search at this file. It is only valid in a file found by discovery.
- `extends` lists files, relative to the declaring file or absolute. They apply before the declaring file, in
  order. A file reached twice applies once. A cycle, a missing file or more than 16 nested files is an error naming
  the file.
- `reset` discards what was inherited for the listed keys before this file applies. Allowed values:
  `version-groups`, `semver-groups`, `ignore`, `dependency-families`, `overrides`.

### Merge rules

| Value | Rule |
| --- | --- |
| Scalars (`fail-on-warnings`, `package-manager`, `mode`, ...) | The later file replaces |
| Tables (`[workspace]`, `[lint]`, `[policy]`, `[catalog]`, `[js]`, ...) | Merge key by key |
| Arrays of strings | The later file replaces |
| `extend-ignore-packages` (`[workspace]`), `extend-ignore`, `extend-ignore-dependencies`, `extend-ignore-binaries` (`[js]`), `extend-exclude` (`[catalog]`) | Append to the inherited list, after the plain key of the same file |
| `[rules]` | Per rule: a level keeps the inherited options; a table of options replaces the options and keeps the level |
| `[js.plugins]` | Per plugin: `true` or `false` keeps the options; a table replaces them |
| `[[ignore]]`, `[[overrides]]` | Append |
| `[[version-groups]]`, `[[semver-groups]]` | The nearer file's entries come first, so with first match wins the project beats the org |
| `[[dependency-families]]` | Replace the family of the same `name`, append the others |

### `[[overrides]]`

```toml
[[overrides]]
packages = ["./legacy/**", "@acme/old-*"]   # directories start with ./, other entries are names
files = ["**/src/generated/**"]             # file globs, anchored at the declaring file
max-level = "warn"                          # cap the severity of matched diagnostics

[overrides.rules]
unused-exports = "off"

[[overrides.ignore]]
rules = ["unlisted-dependencies"]
dependencies = ["jquery"]

[overrides.js]                              # needs packages, no files
entry = ["src/server.ts"]
extend-ignore-dependencies = ["@acme/test-utils"]
```

At least one of `packages` and `files` is required; when both are set a diagnostic must match both. An override
changes how diagnostics in the selected packages or files are reported, and which JS inputs those packages get. It
never changes what a workspace-wide analysis computes, so a package leaves version policy through a root-level
version group with `policy = "ignored"`.

Package-scoped keys, the only ones an override or a package file may hold: `rules` (levels only), `max-level`,
`ignore`, and in `js`: `entry`, `project`, `ignore`, `ignore-dependencies`, `ignore-binaries`, the matching
`extend-` keys and `plugins`. Any other key, including rule options, `js.enabled` and `js.production`, is an error
that names the key, the file and the line. `[lint] max-level` caps a whole root and is allowed in a base file.
A rule that is `off` in the base and on in an override runs; its diagnostics outside the override are dropped.

### Package files

A `skif.toml` in the directory of a workspace member applies to that package only, as if it were an override with
`packages = ["./"]`. It uses the top-level spelling (`[rules]`, `[js]`, `[[ignore]]`, `[lint] max-level`) and the
same package-scoped keys. Its `[[ignore]]` entries need no filter. `root`, `extends` and `[[overrides]]` are not
allowed in it.

### Paths

Patterns that select packages or files in an override, and `extends` paths, are relative to the directory of the
file that declares them. `$ROOT/` at the start of a pattern anchors it at the root being linted instead, which a
shared preset needs. A pattern that would leave its anchor never matches. Values are read in the scope they
configure: top-level `[js]` globs are relative to the root, `js` globs of an override or package file are relative
to each package. `ignore-packages`, `[[ignore]] packages`, group selectors and `[js.workspaces]` keys stay relative
to the root.

### Inspecting the result

`skif config --show` prints the effective configuration of each root as TOML with a `# from <file>:<line>` comment on
every value some file set (the last file to set it, plus the files that appended to a list), and lists the
`skif.toml` files below the root that were not applied, with the reason: only the root's own directory and the
directories of its workspace members are read. `--format json` adds the same as data: `origins` (every key with the
assignments that built it) and `not-applied` (path and reason). `skif config --explain <key> [--package <name>]` prints every file that
touched a key and the final value. `--config <FILE>` lints with that file (and what it extends) only, and
`--no-config` reads no file.

## Selectors

Every key that names packages or dependencies is a list of names and globs. `!` negates, and an invalid pattern is
a configuration error naming the key.

## Full example

```toml
#:schema https://raw.githubusercontent.com/Goldziher/skif/main/schema/skif.schema.json

[workspace]
ignore-packages = ["examples/*"]

[lint]
fail-on-warnings = true

[rules]
unsorted-dependencies = "warn"
empty-dependencies = "off"

[[ignore]]
rules = ["types-in-dependencies"]
packages = ["legacy-app"]

[catalog]
mode = "prefer"

[js]
enabled = true
```

```text
skif [OPTIONS] [PATH]
skif rules [--format human|json]
skif schema
skif init [PATH]
skif config [PATH] [-r] (--show | --explain <KEY> [--package <NAME>]) [--format human|json]
skif explain-usage <FILE[#EXPORT]> [PATH]
skif migrate [PATH] [--from sherif|syncpack|knip|auto,...] [--profile exact|full] [--merge | --force] [--dry-run]
skif list [PATH] [-r] [--show instances,statuses,hints,ignored,all,none] [FILTERS]
skif json [PATH] [-r] [FILTERS]
```

`skif [PATH]` lints the project containing `PATH` (default `.`). The root is resolved in this order:

1. With `-r`/`--recursive`, every root at or below `PATH` (see below).
2. Otherwise the nearest ancestor workspace that lists the package at `PATH` as a member. A package that declares a
   workspace is its own root.
3. Otherwise the package itself, linted in single-package mode: no workspace declaration is needed.
4. When neither `PATH` nor an ancestor holds a `package.json` or a workspace declaration, every root below `PATH`,
   as with `-r`.

The root is used for configuration, reported paths, fix writes and the install step. In a multi-root run (`-r`, or
the fallback in step 4) skif lints each workspace and each standalone package below `PATH` in parallel and merges
the results into one report with one exit code, the worst over the roots. Reported paths are relative to the
invocation directory, human output is grouped by root, and `--format json` adds a `roots` array. `node_modules`,
hidden directories, directories excluded by a `.gitignore` or `.ignore` and directories matching
`[workspace] discover-ignore` (by default `__fixtures__`, `fixtures`, `__mocks__` and `__snapshots__`) are not
searched. A root that cannot be loaded is reported in the `errors` array of the JSON document and does not stop the
others; the exit code is then `2`. A search stopped by the depth limit lists the directories it did not enter in the
`truncated` array. `root-package-manager-field` is not reported for a standalone package below
another root. `--fix` plans, writes and installs per root.

## Subcommands

| Command | Does |
| --- | --- |
| `skif rules` | List every rule with its category, default level and fixability. `--format json` prints one JSON document. |
| `skif schema` | Print the JSON Schema of `skif.toml`. |
| `skif init [PATH]` | Write a starter `skif.toml` into `PATH` (default `.`). Refuses to overwrite an existing configuration. When configuration files above `PATH` already apply, prints a note naming the files the new one inherits from. |
| `skif config [PATH]` | Show how the configuration of the root at `PATH` was built (see below). |
| `skif explain-usage <FILE[#EXPORT]> [PATH]` | Explain why the JavaScript analysis counts a file, or one export of it, as used (see below). |
| `skif migrate [PATH]` | Translate the configuration of sherif, syncpack and knip into a `skif.toml` (see below). |
| `skif list [PATH]` | List every dependency the version groups and the catalog govern, by version group, with its specifiers and states (see below). |
| `skif json [PATH]` | Print every dependency instance the version groups and the catalog govern as one JSON object per line (see below). |

## Flags

| Flag | Meaning |
| --- | --- |
| `-r`, `--recursive` | Lint every workspace and standalone package at or below `PATH` in one run, instead of only the project containing `PATH`. |
| `--format <human\|json\|sarif\|github>` | Output format. Default `human`, or `human` plus GitHub annotations when `GITHUB_ACTIONS=true`. |
| `--output <FILE>` | Write the rendering to `FILE` instead of stdout. Requires `--format`. |
| `--fix` | Apply safe fixes, lint again, then run the package manager's install command. |
| `--fix-unsafe` | Apply safe and unsafe fixes; implies `--fix`. |
| `--dependency`, `--dependency-types`, `--specifier-types`, `--source` | Narrow the version-group policies to some instances (see [Filtering instances](#filtering-instances)). |
| `--dry-run` | With `--fix` or `--fix-unsafe`: plan the fixes and print them as a unified diff, write nothing and run no install (see [Fixing](#fixing)). |
| `--select <highest\|lowest>` | Which version a version alignment fix targets, overriding `[policy] prefer` for this run. |
| `--no-install` | Do not run the package manager after fixing. |
| `--no-prompt` | Never ask which alternative fix to apply; the diagnostic stays unfixed unless `--select` decides. |
| `--max-warnings <N>` | Exit `1` when there are more than `N` warnings. |
| `--fail-on-warnings` | Same as `--max-warnings 0`. Also set by `[lint] fail-on-warnings`. |
| `--rule <ID>=<off\|info\|warn\|error>` | Set a rule's level. Repeatable. |
| `--ignore-rule <ID>` | Turn a rule off. Repeatable. |
| `--ignore-package <NAME>` | Ignore a package by name or glob in every rule. Repeatable. The flags replace `[workspace] ignore-packages` from the configuration files instead of adding to it. |
| `--ignore-dependency <NAME>` | Ignore a dependency in every rule. Repeatable. Adds to the `[[ignore]]` entries of the configuration files. |
| `--ignore-rule-for-package <RULE:PACKAGE>` | Ignore one rule for one package. Repeatable. Adds to the `[[ignore]]` entries of the configuration files. |
| `--require-ignore-reasons` | Fail with exit code 2 when an `[[ignore]]` entry of a configuration file has no `reason`. Entries from flags are exempt. |
| `--config <FILE>` | Use this configuration file (and the files it extends) for every root instead of discovering `skif.toml` files. Conflicts with `--no-config`. |
| `--no-config` | Read no configuration file: the defaults plus the other flags. |
| `--no-js` | Skip JavaScript analysis. Overrides `[js] enabled`. |
| `--production` | Only analyse production code in JavaScript analysis. Overrides `[js] production`. |
| `--color <auto\|always\|never>` | When to colour human output. |

Flags are the top layer of the [configuration precedence](../configuration/#precedence): defaults, then the file,
then the command line. `--ignore-package` replaces the file's `[workspace] ignore-packages`; `--ignore-dependency` and
`--ignore-rule-for-package` add `[[ignore]]` entries to those of the files; `--rule` and `--ignore-rule` set the level of
each rule they name.

## Inspecting the configuration

`skif config [PATH] [-r]` answers which files configure a root and where a value came from. With `-r` it reports every
root at or below `PATH`. Paths are printed relative to the root (or, with `-r`, to `PATH`) with forward slashes.

| Flag | Meaning |
| --- | --- |
| `--show` | Print the configuration files in the order they apply, each as `root`, `ancestor`, `extended by <file>` or `explicit`, then the effective merged configuration as TOML. |
| `--explain <KEY>` | Print every assignment of `KEY` (`lint.fail-on-warnings`, `rules.ID.level`, `js.ignore-dependencies`, `version-groups[0]`), oldest first, as `file:line:column` with the operation `set`, `append`, `prepend` or `reset`, and the final value. A table or list key also lists the keys below it that a file set. |
| `--package <NAME>` | With `--explain`, also list the `[[overrides]]` that apply to the workspace package `NAME`, with the file and line that declared each. |
| `--format <human\|json>` | `json` prints one document with the same `version` and `skif` members as the other JSON outputs. |

An unknown key exits `2` and names the closest keys.

## Explaining usage

`skif explain-usage <FILE[#EXPORT]> [PATH]` answers why a file is not reported as unused, or why an export is not
reported as unused. `FILE` is relative to the current directory, or absolute, and must lie inside the workspace found
at `PATH`. The report names the entry rule when the file is an entry file, lists every import of it with the importing
file and line (and which names the import brings in), and shows the shortest chain of imports from an entry file. With
`#EXPORT` it lists the modules that import that export by name or as a whole, follows re-exports (`export { x } from`,
`export *`) into the modules that use them, and ends with a verdict (`public`, `used` or `unused`) computed from the
same facts as the lines above it. The command builds the whole JavaScript analysis, so it costs as much as the
JavaScript part of a lint run.

| Flag | Meaning |
| --- | --- |
| `--production`, `--config <FILE>`, `--no-config` | Analyse as the lint run with the same flag does. |
| `--format <human\|json>` | `json` prints one document with `version`, `skif` and a `report` member: `file`, `in-graph`, `entry` (the rule that makes the file an entry), `imported-by` (`file`, `line`, `kind`, `names`, `reachable`), `chain-from-entry` and, with `#EXPORT`, `export` (`verdict`, `users`, `re-exports`, `entry-public`, `tagged-public`, `in-used-signature`). |

A file that is not part of the module graph (an unused file, an ignored file, or a file outside the project globs)
exits `2` with the reason; in JSON mode the `error` document carries the same `report`. It also exits `2` when the root
cannot be loaded or the file lies outside the workspace.

## Migrating

`skif migrate [PATH]` reads the sherif, syncpack and knip configuration of the project at `PATH` (default `.`) and
writes a `skif.toml`. It is a one-shot translator: nothing is executed, no file is deleted, and the configuration of
the old tools stays where it is. The [migration guide](../../guides/migrating/) lists what is translated and how.

| Flag | Meaning |
| --- | --- |
| `--from <TOOL>[,<TOOL>...]` | `sherif`, `syncpack`, `knip` or `auto` (default): every tool that has a configuration file, a `package.json` key or a script in the project. |
| `--source <FILE>` | Read this configuration file instead of looking for one. Needs exactly one tool in `--from`. |
| `--profile <exact\|full>` | `exact` (default) keeps only the checks the old tools ran and turns off, in `[rules]`, the other rules skif enables by default. `full` leaves skif's defaults for them. |
| `--output <FILE>` | Write here instead of `PATH/skif.toml`. `-` prints the configuration to stdout. |
| `--merge` | Combine with the existing configuration file (`skif.toml` or `.skif.toml`), which is edited in place: its comments and order stay, tables it lacks are appended under a banner, and in a table both define the existing value wins and lists are united. Values the `exact` profile added (marked with a `# skif migrate: not checked by ...` comment) do not count as existing values, so migrating tools in several steps ends with the same checks as one `--from sherif,syncpack,knip` run. |
| `--force` | Replace the existing configuration file (`skif.toml` or `.skif.toml`, whichever exists). Without `--merge` or `--force` the command refuses to overwrite one. |
| `--dry-run` | Print the configuration to stdout and the report to stderr; write nothing. |
| `--format <human\|json>` | `json` prints one document on stdout with `version`, `skif`, `profile`, `tools`, `translated`, `default`, `needs-human`, `extra-checks`, `notes`, `written`, `kept-existing` and, when nothing is written, `toml`. |
| `--strict` | Exit `1` when any construct needs a human. |
| `--strict-hints` | Write knip's `treatConfigHintsAsErrors` as `stale-js-config = "error"`; by default it is written as `warn`. |

Exit `0` when the file was produced (also when notes need a human, unless `--strict`), `1` with `--strict` and such notes,
`2` when a configuration cannot be read or the output cannot be written.

## Listing instances

`skif list [PATH]` and `skif json [PATH]` show every dependency instance the version groups and the catalog govern,
valid or not, as syncpack's `list` and `json` do. The root is resolved as for linting, `-r` covers every root below
`PATH`, and `--config` and `--no-config` work as for linting. Instances are ordered by version group (the configured
groups in order, then the default group, then the catalog), then dependency name, then where they are declared.
Instances outside the default scope (`[policy] dependency-types`) that no group names are not listed.

The state of an instance is the one a lint run gives it: the syncpack state name of the
[version and catalog policies](../configuration/#version-groups), including the valid states (`IsHighestOrLowestSemver`,
`IsIdenticalToPin`, `IsLocalAndValid`, `IsCatalog`, `IsIgnored`, ...). skif's own names are `UnusedGroup`,
`InvalidPin`, `DiffersToOtherCatalog` and `IsIdenticalToCatalog` (a plain version the catalog rules leave alone).
An instance a rule reports carries that rule and its severity; a state whose rule is off, or which an `[[ignore]]`
entry silences, has none. Workspace-protocol and dependency-family findings are left to the lint run.

`skif list` prints one line per dependency under a heading per version group: the worst severity (`ok` when every
instance is valid, `-` when a state is not reported), the name and the distinct specifiers. `--show` takes a comma
separated list: `instances` adds a line per instance, `statuses` the state names, `hints` marks dependencies that
are workspace packages, `ignored` lists the dependencies of `ignored` groups, `all` and `none` set everything.
The default is `hints,statuses`.

`skif json` prints one object per instance with `dependency`, `dependencyType` (`prod`, `dev`, `peer`, `optional`,
`local`, `resolutions`, `overrides`, `pnpm-overrides` or a custom type), `property`, `package` (the file, relative
to the root), `packageName`, `versionGroup` (syncpack's name: `HighestSemver`, `LowestSemver`, `Pinned`, `Banned`,
`Ignored`, `SameRange`, `SameMinor`, `SnappedTo` or `Catalog`), `versionGroupIndex`, `versionGroupLabel`,
`preferredSemverRange`, `statusCode`, `statusType` (`Valid`, `Fixable`, `Unfixable`, `Conflict` or `Suspect`),
`rule`, `severity`, `isLocal`, `actual` and `expected` (each `{ "raw", "type" }`, `expected` `null` when unknown).

Both exit `1` when an instance is reported at `error` severity, `0` otherwise, and `2` when skif could not run.

## Filtering instances

`skif`, `skif list` and `skif json` take syncpack's instance filters. An instance that does not pass is left out
before it is assigned to a version group, so it is neither reported nor aligned with: `--source
packages/app/package.json` checks that package's instances against each other only, as syncpack does.

| Flag | Keeps |
| --- | --- |
| `--dependency <NAME>` | Dependencies whose name matches the name or glob (`react`, `@types/**`, `!eslint`, `$LOCAL`). Repeatable. syncpack calls it `--dependencies`; skif keeps that name for knip's issue-type shortcut. |
| `--dependency-types <TYPES>` | These dependency types, comma separated (`prod,dev`, `!local`, a `[[custom-types]]` name). The list also replaces `[policy] dependency-types` as the scope of the default group for the run, so `--dependency-types peer` checks peer ranges. |
| `--specifier-types <TYPES>` | These specifier types, comma separated (`exact`, `range`, `!workspace-protocol`; the values of `specifier-types` selectors). |
| `--source <GLOB>` | Instances declared in files matching the glob, relative to the root (`packages/*/package.json`, `pnpm-workspace.yaml`). Repeatable. Unlike syncpack's `--source`, it does not change which packages make up the workspace. |

The filters apply to the version-group and semver-group rules (`version-mismatch`, `banned-dependency`,
`semver-range-mismatch`, `policy-conflict`, `invalid-local-version`) and to the listing; the catalog, workspace
protocol, family and manifest rules see the whole workspace. A configured group that the filters leave without
instances is not reported as unused.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Clean. Warnings within `--max-warnings` are allowed, and `info` never counts. |
| `1` | Problems remain. |
| `2` | skif could not run: invalid or ambiguous configuration, no `package.json` found at or below `PATH`, bad flags, a refused `--fix`, or a failed install step. |

## Output formats

| Format | Output |
| --- | --- |
| `human` | Diagnostics grouped by file, optionally coloured, with a summary. Colour is on only when stdout is a TTY, `NO_COLOR` is unset and the format is `human`. |
| `json` | One versioned document with `version`, `summary` and `diagnostics`; a multi-root run adds a `roots` array with each root's `path`, `packages` and `summary`. Each diagnostic has rule, severity, message, location with line and column span, related locations and fix titles. |
| `sarif` | SARIF 2.1.0 for code scanning. |
| `github` | GitHub Actions workflow-command annotations. |

In `--format json` mode stdout holds exactly one JSON document in every case, including failures. A failure is an
`error` document with a `kind` (`config`, `workspace`, `io`, `usage`, `ci-refusal` or `internal`, a bug in skif), a message and, when known,
`path`, `line` and `column`. `--output` never receives an error document: on failure the file is not written and
the error goes to stdout.

## Fixing

`--fix` applies fixes marked `safe`; `--fix-unsafe` also applies `unsafe` ones. A fix run:

1. Lints and builds the fix plan, selecting fixes by `--fix` or `--fix-unsafe` and `--select`.
2. Writes the plan, atomically per file.
3. Lints again on the changed tree. The report and exit code come from this second run, so exit `1` means problems
   remain after fixing.
4. Runs the detected package manager's `install` in the workspace root, unless `--no-install` was given, no file
   changed, or no package manager was detected. If the install fails the fixes stay written and the exit code is `2`.

`--dry-run` stops after step 1: human output shows `Would fix ...` and a unified diff per file before the report of
the unchanged tree, and `--format json` adds `"dry-run": true` and a `changes` array (`path`, `kind` `modify`,
`create` or `delete`, and `diff`) to the `fix` object. The exit code is the one of the unchanged tree. A dry run is
allowed in CI.

skif's own process never opens a network connection and never resolves a version. The only network traffic comes
from your package manager during the install step.

## CI behaviour

`--fix` and `--fix-unsafe` are refused with exit `2` when `CI` is truthy: set, not empty after trimming, and not
one of `0`, `false`, `no` or `off` in any case. Linting without `--fix` is never affected. On GitHub Actions, with
no `--format`, skif prints the human report plus workflow annotations.
